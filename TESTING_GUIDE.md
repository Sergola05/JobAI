# Руководство по тестированию JobAI

## Предварительные требования

1. **SQL Server LocalDB** должен быть установлен
2. **.NET 8.0 SDK** должен быть установлен
3. **Visual Studio** или **Visual Studio Code** для запуска проектов

## Шаг 1: Подготовка базы данных

Перед запуском сервера нужно применить миграции к базе данных:

```powershell
# Перейдите в папку сервера
cd JobAI.Server

# Примените миграции
dotnet ef database update
```

Если команда `dotnet ef` не найдена, установите инструменты EF Core:
```powershell
dotnet tool install --global dotnet-ef
```

## Шаг 2: Запуск сервера

### Вариант 1: Через Visual Studio
1. Откройте решение `JobAI.sln`
2. Установите `JobAI.Server` как стартовый проект
3. Нажмите F5 или выберите профиль "http" для запуска
4. Сервер запустится на `http://localhost:5143`
5. Автоматически откроется Swagger UI: `http://localhost:5143/swagger`

### Вариант 2: Через командную строку
```powershell
cd JobAI.Server
dotnet run
```

Сервер будет доступен по адресу: `http://localhost:5143`

## Шаг 3: Тестирование через Swagger

1. Откройте браузер и перейдите на `http://localhost:5143/swagger`
2. Вы увидите все доступные API endpoints

### Тест 1: Создание вакансии
- Найдите `POST /api/Vacancies`
- Нажмите "Try it out"
- Введите тестовые данные:
```json
{
  "title": "Разработчик .NET",
  "company": "Технологии будущего",
  "location": "Москва",
  "sourceUrl": "https://example.com/vacancy",
  "description": "Требуется опытный разработчик .NET с опытом работы с ASP.NET Core"
}
```
- Нажмите "Execute"
- Сохраните `id` созданной вакансии

### Тест 2: Получение списка вакансий
- Найдите `GET /api/Vacancies`
- Нажмите "Try it out" → "Execute"
- Проверьте, что ваша вакансия в списке

### Тест 3: Генерация сопроводительного письма
- Найдите `POST /api/CoverLetters/generate`
- Нажмите "Try it out"
- Введите данные (используйте `id` вакансии из шага 1):
```json
{
  "vacancyId": 1,
  "candidateName": "Иван Иванов",
  "candidateContacts": "ivan@example.com, +7-999-123-45-67",
  "candidateSkills": "C#, ASP.NET Core, Entity Framework, SQL Server",
  "candidateExperience": "5 лет опыта разработки на .NET, работал над крупными проектами"
}
```
- Нажмите "Execute"
- Дождитесь ответа (генерация может занять 10-30 секунд)
- Проверьте, что письмо сгенерировано

### Тест 4: Получение писем по вакансии
- Найдите `GET /api/CoverLetters/by-vacancy/{vacancyId}`
- Введите `vacancyId` из шага 1
- Нажмите "Execute"
- Проверьте список писем

## Шаг 4: Запуск WPF-клиента

### Вариант 1: Через Visual Studio
1. Убедитесь, что сервер запущен
2. Установите `JobAI.Client.WPF` как стартовый проект
3. Нажмите F5 для запуска

### Вариант 2: Через командную строку
```powershell
cd JobAI.Client.WPF
dotnet build
# Затем запустите .exe из bin/Debug или bin/Release
```

## Шаг 5: Тестирование через WPF-клиент

1. **Проверка подключения к серверу:**
   - При запуске клиент должен загрузить список вакансий
   - Если список пуст, нажмите "Обновить"

2. **Добавление вакансии:**
   - Нажмите "Добавить"
   - Заполните форму
   - Нажмите "Сохранить"
   - Проверьте, что вакансия появилась в списке

3. **Генерация письма:**
   - Выберите вакансию из списка
   - Нажмите "Сгенерировать письмо"
   - Заполните данные о кандидате
   - Нажмите "Сгенерировать"
   - Дождитесь завершения (может занять время)
   - Проверьте, что письмо появилось в списке справа

4. **Просмотр письма:**
   - Выберите письмо из списка
   - Проверьте, что текст отображается в нижней панели

## Возможные проблемы и решения

### Проблема: "Cannot connect to database"
**Решение:**
- Убедитесь, что SQL Server LocalDB запущен
- Проверьте строку подключения в `appsettings.json`
- Примените миграции: `dotnet ef database update`

### Проблема: "Perplexity API error"
**Решение:**
- Проверьте, что API ключ правильный в `appsettings.json`
- Убедитесь, что есть интернет-соединение
- Проверьте баланс API ключа Perplexity

### Проблема: Клиент не подключается к серверу
**Решение:**
- Убедитесь, что сервер запущен на порту 5143
- Проверьте URL в `ApiClient.cs`: `http://localhost:5143`
- Проверьте, что нет блокировки файрволом

### Проблема: "404 Not Found" при вызове API
**Решение:**
- Проверьте регистр в URL (должно быть `api/CoverLetters`, а не `api/coverletters`)
- Убедитесь, что контроллеры находятся в папке `Controllers`

## Проверка логов

Сервер выводит логи в консоль. Обратите внимание на:
- Сообщения о подключении к базе данных
- Ошибки при вызове Perplexity API
- Ошибки валидации данных
